## 지금 상태 한눈에 (2026-08-04 기준 · 5회차까지 반영)

### 🔴 지금 막혀 있는 것 (5회차에서 확인)

1. **`back/.env`의 OpenAI 키가 OpenAI에서 거부된다** — 앱을 거치지 않고 `api.openai.com/v1/models`에
   직접 요청해 **401 `invalid_api_key`**. 형식·길이는 정상이므로 폐기됐거나 다른 계정의 키다.
   **유효한 키로 교체해야** AI 판단도 RAG 임베딩도 살아난다.
2. **`.env`를 고쳐도 서버는 안 읽는다** — `settings`는 프로세스 기동 시 1회만 만들어지고
   uvicorn 리로더는 `*.py`만 감시한다. **반드시 `back/`에서 재시작**(`env_file=".env"`는 CWD 기준).
3. **yfinance가 429(Rate limited)** 상태였다 — 상류 문제라 코드로 못 고친다. 시간이 지나면 풀린다.

### AI 토큰을 쓰는 곳 — 여기만 돈이 나간다

**앱 전체에서 LLM SDK를 import하는 파일은 [`llm.py`](../back/app/integrations/llm.py) 하나뿐이다.**
의도적인 설계이고, 그래서 프로바이더 교체가 파일 하나로 끝난다.

```
llm.py  ask_structured → agents/analysts.py   에이전트 3인 (병렬, 5회차부터 구조화)
                       → agents/decision.py   최종 판단 1회
        embed_texts   → services/rag_service.py  색인·검색 (5회차 신설)
                              ↓
        services/advice_service.py    일괄 응답
        services/advice_stream.py     SSE 4단계
                              ↓
        POST /api/v1/stocks/advice
        POST /api/v1/stocks/advice/stream
```

**종목 1개 분석 = LLM 4회 + 임베딩 1~N회** (AI 저널리스트 · AI 경제학자 · AI 애널리스트 병렬 +
AI 의사결정자, 여기에 새 뉴스가 있을 때만 임베딩이 추가된다 — 이미 색인된 기사는 건너뛴다).

| 토큰을 쓰는 것 | 토큰을 안 쓰는 것 (전부 yfinance·KRX) |
|---|---|
| `POST /stocks/advice` | `/markets/overview` · `/markets/movers` |
| `POST /stocks/advice/stream` | `/stocks/history` · `/stocks/content` · `/stocks/fundamentals` |
| RAG 임베딩 (색인 시 새 문서만 · 검색 시 질의 1회) | `/stocks/suggestions` · `/stocks/listed-companies` · `/health` |

프런트 진입점: [`api/stocks/advice/route.ts`](../front/src/app/api/stocks/advice/route.ts)(BFF) →
[`useAiAdvice`](../front/src/features/advice/hooks/useAiAdvice.ts)(1종목) ·
[`useBulkAdvice`](../front/src/features/advice/hooks/useBulkAdvice.ts)(관심종목 일괄).

## 1회차 — 2026-08-04 · 재무·밸류에이션 기능 추가

### 왜 했나

"주식에 관심 있는 사람들이 뭘 보는지" 조사한 결과, 개인 투자자의 관심은
**수급 · 배당 · 실적 · 밸류에이션**에 몰려 있었다. 반면 이 서비스는 "차트 + AI 코멘트"만 있고
상위 관심사 6개 중 5개가 없었다. 그중 **밸류에이션과 배당**은 이미 설치된 `yfinance` 하나로
전부 조달되므로 투입 대비 회수가 가장 좋다고 판단해 먼저 했다.

부수적으로 AI 에이전트가 기술적 지표(SMA·볼린저)만 보고 판단하는 문제도 있었다 —
"PER 176배인데 BUY"가 나올 수 있는 구조였다.

### 무엇이 생겼나

1. **`GET /api/v1/stocks/fundamentals`** — PER·PBR·EPS·BPS·ROE·시가총액·배당수익률·주당배당금·
   배당락일·다음 실적발표일 + 연간 매출/영업이익 4개년. 종목당 15분 TTL 캐시(심볼별 락).
2. **재무 탭이 실데이터로 채워짐** — 전에는 "재무 화면은 아직 설계되지 않았습니다"만 뜨던 빈 껍데기였다.
3. **우측 레일에 밸류에이션 3행 상시 노출** (`ValuationRail`) — 재무는 세 번째 탭이라 기본으로
   가려지는데, "지금 비싼가/얼마 주나"는 클릭 없이 보여야 하는 축이라 요약을 따로 뺐다.
4. **AI 판단이 밸류에이션을 봄** — `build_context`(에이전트 3인)와 `decide`(최종 판단) 양쪽에 주입.

### 반드시 기억해야 할 함정 3개 (실측으로 확인)

계획 단계에서 세운 가정 중 셋이 실제 호출로 뒤집혔다. **직관과 반대라 다음에 또 밟는다.**

| # | 함정 | 실측 근거 |
|---|---|---|
| 1 | **국내 종목은 `info["trailingPE"]`가 항상 `None`** | 005930.KS · 000660.KS · 247540.KQ 전부 `None`, AAPL만 34.84. `get_valuation_measures()`가 유일한 경로이고 **yfinance ≥ 1.5**에만 있다 |

## 2회차 — 2026-08-04 · LLM 프로바이더 Anthropic → OpenAI 교체

### 왜 했나

OpenAI(GPT) API 키를 확보해서 프로바이더를 옮겼다.

### 무엇이 바뀌었나

**바뀐 것은 [`llm.py`](../back/app/integrations/llm.py) 한 파일과 설정 4줄뿐이다.**
에이전트·서비스·엔드포인트 코드는 한 줄도 안 건드렸다 — `ask_text`/`ask_structured`
두 함수로 경계를 잡아둔 설계가 실제로 값을 한 번 했다.

| 항목 | 전 (Anthropic) | 후 (OpenAI) |
|---|---|---|
| SDK | `AsyncAnthropic` | `AsyncOpenAI` |
| API | Messages | **Responses** |
| 자유 서술 | `beta.messages.create` | `responses.create` |
| 구조화 출력 | `beta.messages.parse(output_format=)` | `responses.parse(text_format=)` |
| 시스템 프롬프트 | `system=` | `instructions=` |
| 토큰 상한 | `max_tokens=` | `max_output_tokens=` |
| 추론 강도 | `thinking` + `output_config.effort` | `reasoning={"effort": ...}` |
| 거절 감지 | `stop_reason == "refusal"` | 출력 블록의 `content.type == "refusal"` |
| 설정 | `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | `OPENAI_API_KEY` / `OPENAI_MODEL` |
| 기본 모델 | `claude-opus-5` | `gpt-5.4` |

**없어진 설정**: `LLM_SERVER_SIDE_FALLBACK` — Anthropic 전용 베타(거절 시 서버 측 대체 모델
재실행)라 대응 개념이 없다. 없어도 앱은 규칙 기반으로 자체 폴백하므로 기능 손실은 없다.

**그대로인 설정**: `LLM_MAX_TOKENS` · `LLM_EFFORT` · `LLM_TIMEOUT_SECONDS` · `LLM_MAX_RETRIES`.
`llm_effort`의 값(`low`~`max`)이 OpenAI `reasoning.effort`와 그대로 맞아떨어져 운이 좋았다.

의존성에서 `anthropic`을 제거했다. `openai`는 원래 "설치만 되고 안 쓰는 의존성"이었는데
이제 실제로 쓴다.

### 새로 생긴 주의점

- **`LLM_EFFORT`는 gpt-5 계열·o 시리즈에서만 유효하다.** 비추론 모델을 `OPENAI_MODEL`에 넣으면
  `reasoning` 파라미터에서 400이 날 수 있다.
- **추론 토큰도 `LLM_MAX_TOKENS`를 함께 먹는다.** 이 값이 낮으면 본문이 빈 채로 `status=incomplete`가
  된다. 그대로 두면 상위에 "빈 응답"으로만 보여 원인을 못 찾으므로 `_guard()`에서 WARNING을 남긴다.
- **키가 없으면 클라이언트 생성 시점에 바로 예외가 난다.** Anthropic SDK는 호출 시점까지 미뤘다.
  다만 `get_client()`가 `ask_*` 안에서 지연 호출되고 에이전트 계층이 예외를 잡으므로,
  **동작은 전과 같다** — 200 응답 + `agents[*].status="fallback"` + `decision_source="fallback"`.
  (검증함)

### 키 넣는 법

`back/.env`는 gitignore돼 있고 지금 **파일 자체가 없다.** 만들어야 한다:

```bash
cd back
cp .env.example .env
# .env 를 열어 OPENAI_API_KEY=sk-... 를 채운다
```

넣은 뒤 라이브 검증:

```bash
uv run python -m scripts.verify_llm
```

3단계가 독립적으로 실패 원인을 좁힌다: ① 자격 증명·모델 접근 → ② `ask_text` 요청 형태 →
③ `ask_structured` 구조화 출력. 통과하면 실제 엔드포인트에서 `agents[*].status`가 전부
`"done"`인지 확인한다 — `"fallback"`이면 LLM이 아니라 규칙 기반으로 답한 것이다.

### 검증

`ruff` 통과, 테스트 97개 전부 통과. 키 없는 상태에서 3에이전트 → `fallback`,
최종 판단 → 규칙 기반으로 정상 degrade 확인 (예외가 밖으로 새지 않음).

**아직 못 한 것**: 실제 키로 네트워크 왕복을 돌려보지 않았다. `.env`에 키를 넣고
위 `verify_llm`을 한 번 돌려야 이 교체가 진짜로 끝난다.

### 왜 했나

"주식을 잘 모르는데 첫 화면에서 뭘 봐야 할지 모르겠다"가 출발점이었다. 문제가 셋이었다.

### 실시간 시세(Socket.IO) 검토 — 하지 않기로 했다

"장중에 Socket.IO나 폴링으로 실시간 주가를 보여주고 싶다"는 요구가 있었다. 실측해보니
**원천 데이터가 실시간이 아니었다.**

```
info.exchangeDataDelayedBy = 20      ← 야후가 KRX 를 20분 지연으로 준다고 명시
1분봉 360개 = 09:00 ~ 14:59          ← 장 마감 15:30 인데 마지막 31분치가 아예 없음
```

전송을 아무리 빠르게 해도 **20분 전 가격을 더 자주 보여주는 것**뿐이다. 게다가
서버→클라 단방향만 필요해 WebSocket 자체가 과하고(이미 SSE 인프라가 있다),
`CONVENTIONS.md`는 "폴링 금지"를 명시한다.

**결정**: 전송을 바꾸는 대신 **지연 사실을 정직하게 고지**한다. 진짜 실시간이 필요해지면
그때는 전송이 아니라 데이터 소스(한국투자증권 KIS OpenAPI)를 바꿔야 한다.

## 5회차 — 2026-08-04 · AI 판단 실패 원인 규명 + RAG 1단계

### 5-1. "키를 넣었는데 AI가 거절된다" — 원인 두 개

Supabase 미연결이 원인일 것이라는 가설이 있었으나 **아니었다.** 실측으로 원인 둘을 분리했다.

**원인 ① 실행 중인 서버에 키가 없었다.**

BFF로 실제 스트림을 받아보니 세 에이전트 전부 `Missing credentials ... set the OPENAI_API_KEY`였다.
시각을 대보면 명확하다.

| | 시각 |
|---|---|
| 백엔드 프로세스 기동 | 21:58:45 |
| `back/.env` 마지막 수정 | **22:16:10** |

**서버가 떠 있는 상태에서 키를 추가**했고, `settings`는 import 시점 1회만 만들어지며 uvicorn
리로더는 `*.py`만 감시한다 → `.env`를 고쳐도 재시작되지 않는다. **재시작이 필요하고,
`env_file=".env"`가 CWD 기준이라 반드시 `back/`에서 띄워야 한다.**

**원인 ② 그 키 자체가 OpenAI에서 거부된다.**

앱을 거치지 않고 `.env`의 키만으로 `https://api.openai.com/v1/models`에 직접 요청 →
**401 `invalid_api_key`**. 형식은 정상(164자, `sk-proj-`, 공백·따옴표·비ASCII 없음),
OS 환경변수 충돌 없음, DNS·TCP 443 정상, 프록시 없음. 403(권한)이 아니라 401(모르는 키)이라
폐기됐거나 다른 계정/프로젝트의 키다. **재시작만으로는 안 되고 키를 갈아야 한다.**

**Supabase가 아닌 근거**: 코드 전체에 `supabase` 참조 0건, `DATABASE_URL`은 로컬 SQLite이고
정상 동작 중(검색·랭킹이 뜬다), 무엇보다 401은 DB를 거치지 않는 경로에서 났다.
AI 판단 경로는 DB를 읽지 않는다 — yfinance + OpenAI뿐이다.

**진단이 어려웠던 이유도 고쳤다.** LLM 실패는 전부 폴백으로 흡수되어 화면에는 "실패" 배지만
남고 원인 문자열은 SSE에만 실려 있었다. 5-2에서 근거·성향을 화면에 올리면서 이 사각지대도 줄었다.

### 5-2. RAG 1단계 — Supabase pgvector + 하이브리드 검색

**결정 사항** (선택지 검토 후): 벡터 스토어는 **Supabase pgvector**, 그래프 런타임은
**LangGraph**(2단계로 미룸), 이번 범위는 **1단계 RAG 기반**까지.

**왜 했나** — 에이전트가 받던 문서가 "가장 최근 뉴스 3건"이었다. 최신순은 관련성과 무관해서
지수 편입 공지나 배당 기준일 안내가 실적 악화 기사보다 앞자리를 차지한다.

```
수집(yfinance) → 청킹 → 임베딩 → pgvector 적재
                                      ↓
질의 ──┬─ 벡터 검색(의미)   ─┐
       └─ 키워드 검색(어휘) ─┴─ RRF 융합 → 상위 K → 프롬프트 + 인용
```

**새 파일**

| 파일 | 역할 |
|---|---|
| [`services/rag_service.py`](../back/app/services/rag_service.py) | 색인·검색·RRF 융합. 실패를 전부 흡수하는 경계 |
| [`repositories/document_chunk.py`](../back/app/repositories/document_chunk.py) | pgvector 원시 SQL. 멱등 `ensure_schema` + HNSW·트라이그램 인덱스 |
| [`core/vector_database.py`](../back/app/core/vector_database.py) | 주 DB와 분리된 엔진 + Supabase URI 정규화 |
| [`domain/chunking.py`](../back/app/domain/chunking.py) | 문단→문장 경계 분할 (순수 함수) |
| [`scripts/verify_rag.py`](../back/scripts/verify_rag.py) | 5단계 라이브 검증 **겸 최초 스키마 부트스트랩** |
| [`tests/test_rag.py`](../back/tests/test_rag.py) · [`test_advice_stream.py`](../back/tests/test_advice_stream.py) | 13 + 5개 |

**설계에서 지킨 것**

- **두 검색기를 함께 쓴다.** 벡터는 "실적 부진"과 "어닝 쇼크"를 묶지만 종목코드·수치에 약하고,
  트라이그램은 그 반대다. 점수 스케일이 전혀 다르므로(코사인 거리 vs 트라이그램 유사도)
  정규화해 더하지 않고 **순위만 쓰는 RRF**로 합친다 — 스케일 가정이 코드에 스며들지 않는다.
- **키워드 검색은 `word_similarity`(`<%`)를 쓴다.** 일반 `similarity()`는 짧은 질의와 긴 본문을
  통째로 비교해 항상 낮게 나온다. 한국어라 형태소 사전이 필요한 `tsquery`보다 트라이그램이 안전하다.
- **벡터 DB는 주 DB와 엔진을 분리한다.** 로컬 주 DB가 SQLite라 `vector` 확장을 못 올리고,
  같은 `Base.metadata`에 얹으면 개발용 `create_all()`이 깨진다.
- **인용을 검증한다.** 에이전트는 `cited_doc_ids`로 doc_id를 돌려주고
  [`resolve_sources()`](../back/app/agents/analysts.py)가 **실제 검색 결과에 없는 ID는 버린다.**
  모델이 `D9`를 지어내는 일이 있는데, 없는 출처가 "근거"로 뜨는 건 근거가 없는 것보다 나쁘다.
- **RAG 실패 ≠ 판단 실패.** 미설정·연결 실패·타임아웃 전부 빈 목록으로 흡수되고, 그때는
  프롬프트의 근거 규칙이 "문서가 없으면 뉴스를 언급하지 마라"로 작동한다.
- **재임베딩을 건너뛴다.** `doc_key`(URL 해시)로 이미 색인된 기사를 판별한다. 안 하면 같은 기사
  임베딩 비용이 요청 수에 비례한다.

**곁다리로 채워진 것** — 하위 에이전트를 `ask_text` → `ask_structured`(`AnalystOutput`)로 바꾸면서
프런트가 오래 비워 두고 있던 **`stance`(긍정·중립·부정 배지)와 근거 목록**이 채워졌다.
`screen-spec.md`의 미구현 항목 O-02가 해소돼 목록에서 뺐다.

**설정** (전부 `back/.env.example`에 주석과 함께 있다)

### P0 — RAG 2단계 (다음 작업, LangGraph)

**시작 전 전제 두 개** (5회차에서 못 끝낸 것):

1. `back/.env`에 **유효한 OpenAI 키** — 임베딩도 같은 키를 쓴다. 넣고 `back/`에서 **재시작**
2. `back/.env`에 **`VECTOR_DATABASE_URL`**(Supabase URI) → `uv run python -m scripts.verify_rag`
   한 번이면 확장·테이블·인덱스 생성부터 검색까지 확인된다

그다음 1단계의 선형 코드를 상태 그래프로 옮긴다. 핵심은 **조건부 엣지와 루프**다 —
"검색이 부실하면 질의를 고쳐 다시 찾는다", "근거 없는 판단이면 다시 만든다"가 코드가 아니라
그래프 구조로 표현되는 것이 목적이다.

```
            route (종목 정규화·캐시)
                    │
      ┌─────────────┼─────────────┐
      ▼             ▼             ▼
   price        retrieve      fundamentals      ← 병렬 fan-out
      └─────────────┼─────────────┘
                    ▼
              grade_docs  ── 관련성 부족 ──→ rewrite_query ──┐
                    │◄──────────── 최대 2회 루프 ────────────┘
      ┌─────────────┼─────────────┐
      ▼             ▼             ▼
  저널리스트     경제학자      애널리스트         ← 각자 필요한 문서만 인용
      └─────────────┼─────────────┘
                    ▼
                 decide (구조화 출력)
                    ▼
                 verify  ── 인용 불일치 ──→ decide 재시도 1회 → 규칙 폴백
```

- `langgraph`만 추가하고 **노드 안에서는 기존 `llm.py`를 그대로 쓴다** — "LLM SDK를 import하는
  파일은 하나"라는 원칙을 깨지 않는다.
- 프런트와의 계약인 **SSE 4단계는 유지**한다. 그래프 노드 수가 늘어도 이벤트는 4개다.
- 1단계의 `build_query()`가 그래프의 `rewrite_query` 노드로 승격된다 (지금은 고정 질의).
